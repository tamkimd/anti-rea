# Flutter Todo example target

This is a private Anti-REA harness for [`Gaygysyz05/flutter-todo-app`](https://github.com/Gaygysyz05/flutter-todo-app/tree/9df0dc821ff020b42a5ac459c0f2e1ba09d3f9a8), pinned at commit `9df0dc821ff020b42a5ac459c0f2e1ba09d3f9a8`. GitHub identifies the upstream app as MIT-licensed; retain its [`LICENSE`](https://github.com/Gaygysyz05/flutter-todo-app/blob/9df0dc821ff020b42a5ac459c0f2e1ba09d3f9a8/LICENSE) and attribution when using its code. No upstream application source is vendored here.

The repo includes Android and web runners. The Android build needs the Android SDK licenses accepted; Anti-REA's read-only host probe currently reports that prerequisite as blocked. Its Flutter Android lane can capture an obfuscated APK baseline, but it has no Flutter candidate transform or before/after app behavior verifier yet.

The captured Anti-REA baseline built all 39 regular files under `build-out/web` in 15.4 seconds and ran the browser journey on the same private snapshot. Its report records one pass and zero failures for adding a task and marking it complete; the baseline manifest binds the report, snapshot tree, pinned runtime, and each artifact hash. The exact build output, sanitized baseline manifest, verbatim e2e `report-1`, and REA diagnostic outputs are in [`evidence/`](evidence/), with hashes and results in `evidence-summary.json`. The sanitized manifest and REA diagnostic JSON redact temporary filesystem paths; each diagnostic entry records its upstream raw-output hash.

REA 6.8.0 produced a valid limited-scope report for the generated 13 KB `build-out/web/flutter_bootstrap.js` loader: one JavaScript file parsed, zero skipped files or parse failures, and nine findings. See the concise [`REA result`](REA-RESULT.md) and the hash-bound [`raw report`](evidence/rea-bootstrap-report-001.json) for its scope, hashes, complete summary-view coverage, and limitations. This loader report does not cover the Flutter Todo Dart application code.

The app-level analysis remains blocked. A full-snapshot attempt stopped at REA's 300-second per-source deadline. A primary-bundle attempt returned an upstream summary with zero parsed JavaScript files and one skipped file after exhausting its default 1 GiB worker heap. A 4 GiB, 900-second retry timed out. A further 600-second retry used a 4 GiB heap and strict semantic-retention caps (64 nodes per source); it also timed out during parser/static analysis. Its sanitized partial-evidence diagnostic is [`evidence/rea-attempt-004-low-semantic-timeout.json`](evidence/rea-attempt-004-low-semantic-timeout.json). Anti-REA rejects app-level reports with no parsed JavaScript, skipped JavaScript, or parse failures, even when REA labels the view complete. An additional Flutter 3.47.8 release build with JS minification disabled emitted an 8.2 MB app bundle; REA still timed out after 600 seconds with a 4 GiB heap before parsing any file. Its sanitized diagnostic is [`evidence/rea-attempt-005-unminified-timeout.json`](evidence/rea-attempt-005-unminified-timeout.json). The 2,683,181-byte main bundle remains outside BLA's 1 MiB input limit and no candidate was run.

To reproduce the baseline, build from the pinned checkout with `PUB_HOSTED_URL=https://pub.dev flutter pub get` followed by `flutter build web --release --output=build-out/web`. Pass every regular file recursively under `build-out/web` with a repeated `--artifact` option, placing `build-out/web/main.dart.js` first so the browser evidence identifies the app bundle. The current upstream `pubspec.lock` names `pub.flutter-io.cn` and could not satisfy `flutter pub get --enforce-lockfile` under Flutter 3.47.8; the captured build used the current pub.dev resolution while restoring the original lockfile afterward. Flutter also creates Linux/Windows plugin symlinks and updates generated tracked files; keep the build in Anti-REA's private snapshot, clean only those generated side effects before browser capture, and retain the fail-closed symlink checks.

The harness files are provided for a standalone browser run too. Copy `e2e.config.mjs` to the checkout root, `tests/behavior.e2e.ts` to its `tests/` directory, and `server.cjs` to `anti-rea-example/server.cjs`; set `ANTI_REA_E2E_RUNTIME` to the same prepared pinned runtime supplied to `anti-rea baseline --e2e-runtime`. The recorded baseline journey covers adding and completing a task; it does not cover persistence, delete, accessibility, or native Android behavior.

The web build emitted `build-out/web/main.dart.js` at 2,683,181 bytes, above Anti-REA's current single-file BLA JavaScript limit of 1 MiB. The Android readiness probe reports unaccepted licenses and no Android device. No candidate was executed and no protection result is claimed.
