# Portable interfaces

Use `anti-rea` CLI commands when available. The current implementation supports bounded read-only project discovery (`inspect`), explicit-command BEFORE capture (`baseline`), limited evidence-based plan creation (`recommend`), binding a concrete plan to a matching baselining run for user review (`submit-plan`), selected single-file BLA execution (`execute-plan`), run status (`status`), linked evidence reporting (`report`), and cancellation (`cancel`), versioned record validation, plan hashing, run initialization, client decision recording, run-state transitions, authorization, immutable evidence records (`record-evidence`), and a record-level `accept` gate. Baseline capture can take an optional behavior argv with one `{artifact}` placeholder for a JavaScript artifact. It retains and hash-binds bounded BEFORE output; a requested plan command must match that capture and is attached to the matching artifact action only. Pass `--e2e-runtime RUNTIME` to `baseline` (or `e2e_runtime` to MCP `start_baseline`) to run pinned browser tests on a private, artifact-hash-bound BEFORE snapshot; `recommend --e2e-behavior` then requires the saved report and execution checks only the candidate against it. `recommend` offers a conditional source-map release review or BLA candidate option when matching artifacts were hashed in the baseline. Its `--profile` / MCP `profile` starting point selects the BLA JavaScript intensity (`low-impact` → `stealth`, `balanced` → `balanced`, `deep-protection` → `maximum`); `custom` requires an explicit intensity. The plan hash binds that selection, and CLI `choose` displays it and each action’s execution settings before approval. BLA execution requires an approved action selection and plan/source hash match; it records BLA invariants and compares baseline, source, and candidate behavior runs; behavior passes only for successful runs with identical bounded stdout, and REA compares baseline-matched project snapshots with run-bound evidence. `accept` requires every selected check to pass. The acceptance gate verifies raw-file paths, sizes, and SHA-256 values, then semantically validates BLA invariants, configured behavior reports, and run-bound REA comparison evidence. It does not independently authenticate upstream producers or prove application protection.

Use the Anti-REA MCP server when the host supports local stdio MCP. It exposes bounded `inspect_project`/`get_target` discovery, compile-only `probe_wasm_module`, `probe_flutter_android_environment`, synchronous `start_baseline` plus asynchronous `start_baseline_async`, evidence-based `create_plan`, `submit_plan`, asynchronously scheduled `execute_plan`, `cancel_run`, `get_run`, `get_report`, `get_evidence`, `save_evidence`, and the record-level `accept_run` gate. `create_plan` returns the complete saved plan in its `plan` field; pass that exact object to `submit_plan` so the decision remains bound to the stored plan hash. The WASM probe never instantiates a module or verifies host bindings. The Flutter probe reports toolchain and connected-device readiness, but it does not build or run an application. `get_report` uses the shared core report assembler to check linked record IDs and target, baseline, plan, decision, execution, verification, and acceptance relationships; terminal acceptance is replayed through the semantic gate, and an unfinished baseline may be absent until capture writes it. This does not authenticate evidence producers. Use `get_evidence` for individual saved evidence records. For asynchronous baseline capture, provide a `run_id`, poll `get_run` until the baseline is saved or the run is terminal, then pass the same run ID to `submit_plan`. `cancel_run` terminates active work, removes incomplete outputs, and can close a completed baseline that has not yet been submitted for planning while retaining its immutable evidence; Windows baseline and REA commands start suspended and use kill-on-close Job Objects; that Windows API path still needs a Windows runtime check. CLI baseline capture remains synchronous. MCP workers are process-local and are not resumable after a crash or forced termination. Discovered manifests and baseline evidence are stored in the Anti-REA private state directory; that directory must be outside the inspected project. Commands execute project/upstream code; timeout and output bounds do not provide OS isolation. Artifact hashing fails closed if the platform lacks safe directory-relative file opens. The server records a decision sent by its client and cannot independently prove a person approved it.

For a harness that supports Skills, install this folder as a Skill. If a harness supports neither Skills nor MCP, provide the user a plan and commands to run in a terminal-enabled environment. Describe compatibility only for harnesses actually tested with a recorded version and workflow. Unknown harnesses remain unverified; provide manual setup instructions without modifying their configuration automatically.

See the [portable handoff reference](harness-fallback.md) for a copy-ready template when execution must move to another environment.

Current entrypoints:

```sh
python3 interfaces/cli/anti_rea.py --help
python3 interfaces/cli/anti_rea.py inspect /absolute/path/to/project --store /absolute/path/to/private/state
python3 interfaces/cli/anti_rea.py baseline /absolute/path/to/project --store /absolute/path/to/private/state --id before-001 --artifact dist/index.html --artifact dist/assets/app.js --artifact dist/assets/site.css --e2e-runtime /absolute/path/to/e2e-runtime --rea-runtime /absolute/path/to/rea-runtime -- npm run build
python3 interfaces/cli/anti_rea.py recommend target-id before-001 plan-001 /absolute/path/to/private/state
python3 interfaces/cli/anti_rea.py status run-id /absolute/path/to/private/state
python3 interfaces/cli/anti_rea.py report run-id /absolute/path/to/private/state
python3 interfaces/cli/anti_rea.py cancel run-id /absolute/path/to/private/state
anti-rea mcp serve  # requires the pinned MCP SDK and Python 3.11+
```

Equivalent launchers are `python3 -m interfaces.mcp.server` and the installed `anti-rea-mcp` entrypoint.

The `anti-rea` package entrypoint is available after installation. The wheel installs the canonical Skill, integration scripts, fixtures, locks, and documentation under `share/anti-rea` in the Python installation data directory. Find that directory with `python -c 'import sysconfig; print(sysconfig.get_path("data") + "/share/anti-rea")'`.
